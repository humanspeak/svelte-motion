## Dependency notes

- 001 is the heart: it rewrites the single write path (`setXYImmediate`)
  in place, so 002–005 all sit on it. It deliberately KEEPS all 18 call
  sites working (inertia/settle/origin/keyboard/constraints call the same
  function) — 003 then simplifies those callers.
- 002 delivers the operator acceptance criterion (hover during glide) and
  retires both pieces of plan-003 scaffolding (the container mirror, the
  dataset guard). The banked risk note applies: the global lock lands ONLY
  in the same plan as the whileDrag `setActive` work, never alone.
- 004 (whilePan) is a svelte-motion EXTENSION with no upstream
  AnimationType — it goes through VE values via `animateTarget`, NOT
  through the animationState's fixed type list. Do not fork animation-state.
- Whole batch remains P2/P3 and deferrable; drag behavior is
  operator-signed-off (#399–#415 and the #449 tour §7) — zero behavioral
  regressions is the bar, BLOCKED-with-clean-report beats a regression.

## Findings considered and rejected

- Landing the drag lock alone as a "cheap first slice": rejected — an
  unreleased global lock kills hover/press everywhere, while the dataset
  flag is per-element self-limiting; lock lands only with 002's setActive
  work (banked ruling).
- Mapping `whilePan` onto the `whileDrag` AnimationType slot: rejected —
  collides when both props are used and misrepresents priority semantics.
- Adopting upstream `VisualElementDragControls` wholesale: still rejected
  (React-shaped props/context); this batch ports the write-path contract.
