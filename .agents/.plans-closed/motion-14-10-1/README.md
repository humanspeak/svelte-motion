## What arrives with the pin bump (no port)

We call this upstream code unchanged. Plan 001 pins the user-visible items:
- **`press()`**: `count`, `countTimeout`, `hold` and `repeat` options, plus the `onActive`, `onHold` and `onRepeat` handlers. We re-export `press` at `src/lib/index.ts:36`. Plan 001 re-exports the types.
- **`drag()` `x`/`y`**, **`DragControlOptions.immediate`** and **`DragConstraintsContext.getProps`**: our runtime wiring is motion-dom's. Plan 005 adds typing, docs and tests.
- **`animate()`**: a timeline made only of nested sequences is now recognised (`e257e1b0e`). Timeline `call()` no longer fires extra times on repeat (`4cf2f4a01`). A timeline is re-registered with its `useAnimate` scope on each replay (`a90c0532f`). `reduceMotion` now applies to sequences on plain elements (`8795896fb`, `123a7679c`). Plan 001 pins the first three.
- **Press released during a drag:** `press/index.ts:232-237` turns it into a cancel, but on a `drag` + `whileTap` element the drag's capture-phase pointerup releases the lock first, so a `count: 1` press still ends as `onTap`. That matches upstream React (drag registers before tap). Only `count` sequences are cancelled by a drag; plan 002 Step 5 tests that. (Corrected 2026-11-06 after plan 001's first run.)
- **Performance** (lazy transform groups, fewer objects per value, memoised `getAnimatableNone`, and more): free.
- **The one break**: `src/lib/html/motionDomSsr.spec.ts`'s fake value lacks `run()`, because upstream switched from `value.start(` to `value.run(`. Plan 001 Step 4 fixes it.

## Findings considered and rejected

- **Keyboard grab kept in a ref (upstream `fe72ef29e`, `246d02dde`): no port needed.** It fixes a React race in which a key sent before React re-rendered missed the grab. Our `grabbedFrom` is Svelte `$state`, which updates synchronously. Plan 003 Step 4 adds the two upstream tests as guards only.
- **Projection transform-string format (`4a0446e6a`, `061470ab2`, `2e77ff99e`): no impact.** The projected-styles cache was added and removed again inside the range, so `create-projection-node.ts` is byte-identical to 14.9.1. Only `projection/styles/transform.ts` changed (a combined `scale()`). Nothing in `src/` parses projection transform strings, and the e2e `'none'` checks all run on settled elements. Watch `e2e/independent-transforms/layout-rotating-3d.spec.ts:82` (`not.toContain('scale')`) on future bumps.
- **`magnetic()`: not relevant.** It was added and then moved to Motion+ inside the range (`a2c7fea36`, `6755db336`). It isn't in 14.9.1 or 14.10.1, so the export allowlist doesn't change.
- **`merge-refs.ts`: not ported.** It handles React 19 callback-ref cleanup. Svelte's `bind:ref` doesn't need it.
- **Size-budget commits, the Remix adapter and the flaky-test fixes: not ported.** They have no runtime surface for this library.
- **Internal transform-animation state we rely on** (`liveValue`, `_animation.tick`, `TransformAnimation.stop/release`): checked, still present at 14.10.1 (`TransformAnimation.ts:305,434`, `value/index.ts:501-522`). The new lazily built transform groups have a "waiting to build" window that is harmless for `stripToBaseTransforms`. Plan 001's full e2e gate covers this.
