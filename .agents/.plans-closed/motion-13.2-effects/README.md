## Findings considered and rejected

- **vgpu docs example**: `vgpu` is a 0.3.1 "scaffold" package with no stable
  API; the subpath re-export (003) is enough until it reaches 1.0.
- **Spring generator "parity pass"** (flagged by the competitive-intel run):
  we import upstream's `spring` rather than porting it, so the 13.2.0 rewrite
  (memoised underdamped sampling, `Math.pow` → multiplication) is inherited
  with zero code change; unit + drag e2e suites passed on 13.2.0.
- **Inertia bounce velocity fix**: `dragInertia.ts` calls upstream `inertia`;
  the analytic-derivative change is inherited. Drag e2e passed 26/27 with the
  one failure re-run 4× green (timing flake in `snap-to-origin`).
- **`calcGeneratorDuration` / `pregenerateKeyframes` signature changes**:
  internal to upstream; nothing in `src/lib` imports them.
- **Free-function `addEffect` / `removeEffect` / `findEffect` / `animateEffectSubject` re-exports**:
  upstream documents the `animate.addEffect` form; the free functions are
  duplicate surface. Import from `motion-dom` if a rare consumer needs them.
- **`styleEffect` / `attrEffect` / `svgEffect` `.get()`**: upstream wraps them
  in `createSelectorEffect`, which strips `.get`; there is nothing to expose.
  Only `propEffect` carries it (handled in 001).
- **`useAnimate` scoped animate gaining `addEffect`**: upstream's scoped
  animate lacks it too; adding it would be a divergence.
- **Pre-existing, unrelated**: `dist/reorder.d.ts` is not emitted
  (`$$IsomorphicComponent` cannot be named) in both the local build and the
  published 0.10.0. Worth its own issue; not part of this initiative.
