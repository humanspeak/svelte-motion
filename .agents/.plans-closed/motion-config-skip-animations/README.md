## Dependency notes

- Single-plan batch; no inter-plan dependencies.
- Plan 001 carries a **secondary fix** that is separable: `MotionConfig.svelte`
  currently does not merge its parent config, so a nested `<MotionConfig>`
  shadows outer props entirely (the public docs claim otherwise, and upstream
  framer-motion merges). Without it, a nested config silently re-enables
  animations inside a `skipAnimations` subtree. It is confined to
  `MotionConfig.svelte` (Step 3) and can be dropped without losing the feature
  — see that step's STOP condition.

## Scope decisions recorded

Carried in the plan, repeated here so they are not re-litigated:

- **`skipAnimations` is NOT folded into `_MotionContainer`'s shared
  `mergedTransition` derived.** That value also feeds the projection adapter's
  `updateOptions({ transition })`, and upstream's `skipAnimations` does not
  skip layout/FLIP projection animations. It is threaded narrowly instead: the
  `VisualElement` option, the `AnimatePresence` `registerChild` call, the
  optimized-appear gate, and `useAnimate`.
- **Drag momentum/inertia and layout/FLIP animations stay animated.** Upstream
  behaves the same way (neither routes through `animateMotionValue`'s `element`
  parameter). Documented as intentional in the docs step.
- **`src/lib/utils/visualElementCore.ts` is not edited.** It already accepts
  and forwards `skipAnimations` (lines 431 / 480 / 496); only the caller was
  missing.

## Findings considered and rejected

- **Reactive post-mount toggling is "beyond upstream", so skip it**: rejected.
  React creates the `VisualElement` once and never re-reads `skipAnimations`,
  but this library's `MotionConfig` exposes reactive property getters and a
  toggle is the natural test-harness shape. The sync effect costs three lines
  (plan Step 4c) and is documented as a deliberate divergence.
- **Exposing `MotionGlobalConfig.skipAnimations` as a library export**: not
  worth doing. Consumers already reach it through the `motion` package, and
  `docs/static/docs/vanilla-values.md:101` already points at it. A scoped
  component prop is the parity gap, not the global.
- **Closing out `.competitive-intel/state.json`**: deliberately out of scope.
  The nightly competitive-intel digest owns that file and reconciles
  `open_gaps` → `closed_gaps` itself.
- **`MotionConfig`'s other upstream props (`features`, `transformPagePoint`,
  `isValidProp`, `nonce`)**: low urgency, tracked separately in the intel
  state's `open_gaps`. Plan 001's parent-config inheritance makes each of them
  a one-field-plus-one-getter addition later.
