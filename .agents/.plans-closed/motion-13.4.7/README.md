## Retarget note (2026-10-01)

Motion 13.4.7 was tagged but never published to npm. Upstream went straight to
**13.5.0** (2026-10-01), so plan 002 was executed against 13.5.0, at the
operator's direction, directly in the session rather than through a dispatched
executor. Deltas from the plan as written:

- Bumped `motion` and `motion-dom` to `^13.5.0` (motion-utils 13.5.0 transitive).
  pnpm 12 has no `--save-prefix`, and caret is the default. The lockfile also gained an
  `integrity` field on the unchanged docs-kit tarball (same commit).
- Ported 13.5.0's `canAccelerateScroll` change (`supportsScrollTimeline() && !offset`):
  a page `useScroll({ offset })` previously ran on a ScrollTimeline and ignored
  its offset. Red-first: one unit test plus e2e `page-accelerated`/`page-box`.
- Test page `/tests/use-scroll/view-timeline-offsets` + e2e (6 tests). Red on
  13.4.6: cover box had no ViewTimeline, and the page box wrongly had a ScrollTimeline.
  Green on 13.5.0.
- Found and fixed a **test-app** defect: `src/routes/app.css` sets
  `overflow-y: auto !important` on html and body, which makes body a frozen scroll
  container, so every ViewTimeline under it stuck at a constant time. The page restores
  `overflow-y: visible` while mounted. Upstream has no guard for this either; the docs
  now warn about it.
- Docs (use-scroll Performance) and `.changeset/motion-13-5-0.md`. The earlier
  useTransform changeset now references 13.5.0.
