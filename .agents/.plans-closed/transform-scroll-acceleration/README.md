## Findings considered and rejected

- **motion#3864 (frameloop `frameData` split for tree-shaking)**: no action.
  `frameData` is still exported from the `motion-dom` barrel as the same object,
  and our imports (`src/lib/utils/pan.ts:38`, `src/lib/index.ts:29`) use the
  package root. A bundle probe on 2026-09-30 (Vite + vite-plugin-svelte, minified,
  built `dist`) showed that our vanilla re-exports tree-shake at parity with
  upstream: `animate` 81.5 KB (identical to importing it from `motion` directly),
  `frame` 2.3 KB, `inView` 1.2 KB, `mapValue` 19.8 KB, `useTransform` 20.9 KB,
  `useScroll` 22.9 KB. Named `MotionDiv` (257.5 KB) matches a direct
  `html/Div.svelte` import (257.6 KB), against 374.6 KB via the `motion` object.
  This matches the docs page's claims. The automated guard (modeled on upstream's
  `frameloop-tree-shaking.test.ts`) is planned in
  `.agents/.plans-closed/tree-shaking-guard/001-bundle-tree-shaking-guard.md`.
- **motion#3865 (CircleCI 2.1)**: upstream CI only.
