## Findings considered and rejected

- **Port #3769 `useCombineMotionValues` catch-up**: React-only. svelte-motion's `useTransform`
  (`src/lib/utils/transform.svelte.ts`) builds on motion-dom's `transformValue`, which subscribes synchronously at
  creation. There's no render→effect gap and no Strict Mode double-invoke.
- **Disable acceleration to keep old e2e assertions passing**: diverges from upstream; stale tests get fixed instead.
- **Direct `style.transform` writers in `src/lib/utils/layout.ts` / `drag.ts` (no-VisualElement path)**: not changed
  pre-emptively. A WAAPI group would override them, but only if one of them writes while a group is accelerated.
  001's full e2e run is the detector. Plan a follow-up only if it implicates them.
