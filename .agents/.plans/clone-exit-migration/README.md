# Implementation Plans — clone-exit-migration

Generated by the improve skill on 2026-07-25, planned at commit `843dc26` (re-stamped).
Follow-up to the visual-element-core batch: direct `<AnimatePresence>`
children still exit via the deep-clone path in `presence.ts` (the documented
architectural deviation from upstream, and the home of the library's last
legacy `animate()` call). The end state is real-node exits through the
already-landed PresenceChild + `setActive('exit')` machinery — but Svelte
unmounts children the consumer stops rendering, so the MECHANISM is a
genuine open design question. This batch therefore starts with a spike.

## Findings considered and rejected

- Migrating without an API/mechanism decision ("just wrap children in
  PresenceChild internally"): impossible as stated — AnimatePresence renders
  an opaque snippet and cannot re-render children the consumer removed;
  that impossibility is why the clone path exists. Hence the spike.
