## Direction suggestions

Options for the maintainer, not ranked against the bugs above. Effort is
coarse. The motion.dev links were not fetched during the audit.

1. **`transformViewBoxPoint` for SVG drag.** Upstream ships a small public
   helper (`packages/framer-motion/src/utils/transform-viewbox-point.ts`) that
   returns a `transformPagePoint` for a scaled `viewBox`. `MotionConfig
   transformPagePoint` is already supported here; the helper is absent from
   `src/lib` and from `motionExportAllowlist.ts`. WOW: drag a `motion.circle`
   inside an SVG with `viewBox="0 0 100 100"` rendered at 500 px and it stays
   under the pointer instead of moving five times too far. Live reference:
   <https://motion.dev/docs/react-drag>. Effort S–M, additive. Trade-off:
   demand is unproven.
2. **Close the React-entry hook gap.** The README's stated goal is that React
   examples translate "with minimal changes", but `useDragControls` (only
   `createDragControls` exists), `usePageInView`, `useInstantTransition`,
   `useAnimateMini` and vanilla `followValue` are neither exported nor
   allowlisted. The export tripwire in `src/lib/index.spec.ts` covers the
   `motion` barrel but not upstream's React entry. WOW: paste the motion.dev
   drag-controls example (press a handle elsewhere and a different element
   starts dragging) and the import line works unchanged. Live reference:
   <https://motion.dev/docs/react-use-drag-controls>. Effort M in total, each
   piece S. Trade-off: more aliases to maintain; extending the tripwire to the
   React entry is the durable part.
3. **Finish `LazyMotion` feature gating (open issue #515).** `domMin`,
   `domAnimation`, `domMax` and `pinchFeatures` are exported and pinch is
   already gated per nearest `LazyMotion`, but animations are not gated on the
   bundle's flag and the README never mentions `LazyMotion`. WOW: the
   bundle-size story, an `m` component whose first paint ships a few kilobytes
   and whose animations switch on when the feature chunk arrives. Live
   reference: <https://motion.dev/docs/react-lazy-motion>. Effort M, risk MED
   (changes behaviour for `m` without a bundle). Best started as a spike that
   defines the no-bundle behaviour and extends the tree-shaking guard to prove
   the size claim.

## Findings considered and rejected

So nobody re-audits them:

- **`LazyMotion` swallows loader rejections** (`LazyMotion.svelte:84-91`): the
  in-code comment records it as a deliberate choice ("publishes nothing, as
  upstream"). Upstream has no `.catch`, so it surfaces an unhandled rejection
  where this stays silent; logging the error in dev would be a small
  improvement, not worth a plan.
- **`trunk-io/analytics-uploader@main` and tag-pinned actions in
  `npm-publish.yml`**: each carries a `zizmor: ignore[unpinned-uses]` comment,
  so the pinning policy is a recorded decision, and the file is managed from
  `humanspeak/docs-kit`. Worth a maintainer look in docs-kit (the `@main` ref
  and the build job's `packages: write` go beyond tag pinning), not a plan in
  this repo. The rest of the release workflow held up: no
  `pull_request_target`, inputs reach `run:` only through `env:`, publishing
  uses OIDC provenance.
- **Single-axis RTL branch in `checkReorder.ts:94-95`**: diverges from
  upstream `check-reorder.ts:57`, but by reading, upstream is the broken side
  (an RTL drag would swap immediately). Not a mechanical port; keep, and
  consider upstreaming.
- **`animate={controls}` is not a controlling variant node** (variant children
  do not follow `controls.start('label')`): real divergence, but the in-code
  comment at `_MotionContainer.svelte:2452-2461` reports ten specs regressing
  when it was tried. Effort M–L, risk HIGH, confidence MED. Needs a spike, not
  an executor plan.
- **`seenKeys` / `exitedKeys` grow per unique key** (`presence.ts:1528-1531`):
  upstream's `exitComplete` map keeps completed keys the same way.
- **Process-wide `holdLayoutIdHandoffs` counter** (`layoutId.ts:66`):
  documented design; only reachable with a hold that never releases.
- **Extracting pop-layout and style-snapshot helpers out of `presence.ts`**
  (about 840 of 3019 lines are standalone): sound, but
  `.agents/.plans/clone-exit-migration` will reshape this file. Sequence it
  after that decision.
- **Coverage thresholds and a unit spec per export**: the export tripwire
  already guards the surface; a threshold would mostly measure the
  4117-line container.
- **Suppression and TODO cleanup**: library source has 0 `TODO`/`FIXME`,
  0 `as any`, 0 `@ts-expect-error`. Nothing to do.
- **Tool-version alignment beyond CONTRIBUTING**: Trunk's hermetic linter
  versions differing from `package.json` ranges is by design.
- **Appear script, `{@html}`, style serialization, `vite.ts` path handling**:
  checked for injection and found sound. The only `{@html}` sink in `src/lib`
  (`_MotionContainer.svelte:4083,4092`) takes `JSON.stringify` output with `<`
  escaped and an id from `$props.id()`. No `innerHTML`, `eval` or
  `new Function` in `src/lib`. No committed secrets found.
- **Dead `buildTransform` / `isSafeTransform` / `parseMatrixScale`** in
  `transform.svelte.ts`: already recorded by the motion-14-5-0 batch; still
  dead, still not exported publicly.
- **Pop-layout e2e flake**: no code-level root cause found. The closed
  14.12.0 guard report attributes it to frame capture under load.
