Generated by the improve skill on 2026-11-12 against `feat/motion-14.12.0` at `82bf6e74`. That is `origin/main` `d1719573` plus one commit (the competitive-intel state refresh). At that commit:

- Standing rule: wherever we diverge from upstream, adopt upstream behaviour.

## What arrives with the pin bump (no port)

- **Vanilla `pinch()`** and its types: a new public export of `motion`. Plan 001 re-exports it (the export tripwire forces that into the bump), plan 003 proves it in a browser.
- **`visualDuration`/`bounce` springs inherit velocity** (`spring.ts`), and `JSAnimation.stop()` measures velocity from the previous frame. Plan 001 pins both with red-first unit tests; plan 002 adds the sign-off page, e2e and docs.
- **A press no longer ends when a non-primary touch lifts** (`press/index.ts`). We call motion-dom's `press()` unchanged (`src/lib/utils/gestures.ts`). Covered by plan 004's "a pinch isn't a tap" e2e tests.
- **`whilePinch` in `variantPriorityOrder`**: we use motion-dom's `createAnimationState`, so priority is free. Plan 004 wires the prop.
- **`VisualElementDragControls.panSession` and `PanSession.history` made public**: used by `pinch()` to hand back to a drag. Our `DragGestureFeature` uses motion-dom's real controls, so nothing to port. Plans 003 and 004 test the hand-off.

## Open question for the maintainer (not planned)

**A bundle without animations.** Upstream's `<LazyMotion features={pinchFeatures}>` on its own gives an `m` component pinch and no animation feature (`animate`, `whileHover` and the rest do nothing). In svelte-motion any loaded bundle enables animations, because `FeatureBundle.animations` has never been read: `_MotionContainer.svelte` only checks `gestures`, `drag` and `layout`. Until now every bundle had `animations: true`, so it never mattered. Plan 004 makes the field optional and leaves the behaviour as is. Matching upstream means gating the animation feature on the flag inside `_MotionContainer.svelte`, which is its own plan with its own risk. Under the standing rule this should be adopted; say the word and it becomes plan 006 (after 004).

## Findings considered and rejected

- **Mirroring upstream's global feature registry for gating.** Upstream's `loadFeatures` mutates one global registry, so a single `LazyMotion` with `pinchFeatures` anywhere turns pinch on for every motion component in the app, mounted before or after. That is a side effect of React's implementation, it contradicts upstream's own JSDoc ("Requires `pinchFeatures` to be loaded via `LazyMotion`"), and module-level state would leak across requests in SvelteKit SSR. Plan 004 registers the feature class globally (it must, the registry is motion-dom's) but passes each node its `pinch` prop only when its nearest `LazyMotion` has the bundle.
- **The feature writing `element.style.touchAction` itself, as upstream's `PinchGesture.update()` does.** Svelte rewrites the whole `style` attribute from a derived string, which would erase an imperative write, and a value captured at mount would be restored stale. Plan 004 appends `touch-action` to that derived string instead; upstream's four touch-action unit tests are ported and must pass against it.
- **Re-typing `pinch()` like `drag()`** (`src/lib/utils/vanillaDrag.ts`): `drag()` was re-typed because its `x`/`y` options take motion values. `pinch()` options take none, so it is re-exported as motion's own binding.
- **Re-exporting `addPinchListeners`**: it has no `@public` tag and is the building block the React feature is made from, like `PanSession`. Allowlisted in 001; 004 imports it from `motion-dom`.
- **Porting `stop-velocity.test.ts`** (the `JSAnimation.stop()` change): it needs motion-dom's internal `Driver` type and hand-set `frameData.isProcessing`. Plan 001's `animate()` interrupt tests cover its user-visible effect.
- **`toTransition` removed from the spring generator**: nothing in `src/` or `docs/src` uses it.
- **Size-budget commits, `dev/` package bumps, the WebKit ctrl + wheel test fix (`9df533983`), "Remove pinch pan cover" (`5a5159dd3`, added and removed inside the range)**: no runtime surface for this library.
- **Exporting `pinchFeatures` from the `@humanspeak/svelte-motion/m` entry**: not checked against upstream's `react-m` entry. It is exported from the main entry, which `m` users already import `LazyMotion` and `domMax` from.
