# Motion 14.7.1 parity

Generated by the improve skill on 2026-10-27 against `origin/main` `f8ac71aa` (v2.6.0 merged as #507, pinned to Motion
14.6.0). Upstream range reviewed: `~/Github/motion` `v14.6.0..v14.7.1` (221 commits; 112 files under `packages/`),
which covers all of 14.7.0 plus the one 14.7.1 fix.

The maintainer asked (2026-10-27) to be fully caught up, so every relevant upstream change became a plan; the
maintainer's standing rule is to adopt upstream behaviour wherever we diverge. Release: **2.7.0**, mirroring Motion
14.7. `package.json` says `2.5.0`; the release workflow bumps the version from the PR's label, which the maintainer
adds. Executors never change `"version"` or add labels.

Not planned (React-only or nothing to port): the `useSpring` `isStatic` trim (f0977dba4), the React gesture-wrapper
refactors, type-only re-export conversions in `framer-motion/src/index.ts`, size-budget commits, and `timeline()`
(added and removed inside the range, never published).

  Never set `PW_REUSE_SERVER`. Docs Playwright uses a fixed port (5201); it runs only in the final gate, alone.
